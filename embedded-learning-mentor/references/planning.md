# 学习规划：长期路线与当前任务

> 本文件在**制定/调整学习计划**时加载。原则：**规划是为了少走弯路，不是为了管理用户。**
> 不擅自决定方向；计划必须能被验收、能被修改。

## 1 两种模式，别混用

| | 长期规划 | 当前任务规划 |
|---|---|---|
| 触发 | "怎么学嵌入式""给我一条路线""半年内达到…" | "帮我搞懂定时器""做一个温控小项目" |
| 时间跨度 | 4 周–12 个月 | 1 次会话–2 周 |
| 产出 | 阶段 + 里程碑 + 考核标准 | 步骤 + 完成标准 |
| 是否入库 | 是（`01_学习路线/`，用户同意后） | 视情况：一次性任务只记 log |
| 强制关联 | 必须 | **不必**纳入长期路线 |

## 2 长期规划：八步

> **先看知识库有没有现成路线**（如 `[[00-01-学习路线与过关标准]]`、`[[00-04-完整学习路线与项目验收清单]]`、`[[学习路线与能力地图]]`）。
> 有就**基于它做评估与排期**，不要另造一套平行路线；缺的部分才补。
> 目标、约束、已有水平已采集过就**直接复用**，不要换个环节再问一遍。

| 步 | 做什么 | 产出 | 常见错误 |
|---|---|---|---|
| 1 | **澄清目标**：做什么、到什么程度、期限、约束（时间/预算/硬件） | 一句可验收的目标 + 约束清单 | 目标写成"学好 STM32" |
| 2 | **评估基础**：读 `00_个人档案/学习状态.md`；缺关键维度就做 1 轮诊断（≤4 题） | 起点状态 | 跳过评估直接排课 |
| 3 | **识别前置**：画出依赖链（C → 数电 → MCU 外设 → 协议 → RTOS） | 前置知识与缺口 | 把前置当"顺便学" |
| 4 | **能力分解**：知识 / 技能 / 工具 / 工程素养四类 | 能力清单 | 只列知识点，不列工具与素养 |
| 5 | **划分阶段**：3–6 个阶段，每阶段 2–6 周；**跨度超过 6 个月**拆成两个周期（各 3–6 阶段），周期间做阶段测试并重估 | 阶段表 | 阶段太多（>8）或太短 |
| 6 | **里程碑**：每阶段 1 个可交付作品 + 1 次阶段测试 | 里程碑与验收判据 | 里程碑是"学完第 3 章" |
| 7 | **理论/实践配比**：每阶段理论 ≤40%，必须有动手产出 | 配比与作品清单 | 全程看视频不动手 |
| 8 | **估时**：按 §5 给区间与假设 | 周数区间 + 假设 | 精确到小时，假装准确 |

完成后**先讨论，再落盘**（§7）。

## 3 路线选项与用户决策

长期方向**必须由用户选**。给 2–3 个路线方案，每个包含：

- 路线名（例：A 单片机主线 / B 硬件主线 / C 平衡路线）
- 适合的人、达成什么
- 阶段数与大致周期
- 代价与风险（例：A 快但模拟电路弱；B 打样成本高）
- 推荐理由（可以推荐，但不能替他决定）

输出格式：

```
路线 A：…（周期 3 个月，每周 8h）　达成：能独立做 STM32 小项目
路线 B：…（周期 5 个月）　　　　　 达成：能独立画板并调试
推荐 A，因为你的目标是"做出来"，且已有 C 基础；代价是模电要后补。
你选哪个？或有别的约束（预算/时间）？
```

用户选定后再进入 §7。**中途允许改路线**（§8）。

## 4 阶段与里程碑

每个阶段必须能回答四个问题：

1. 学什么（知识单元清单）
2. 练什么（作品/实验）
3. 怎么算过（验收判据，可观察、可复现）
4. 怎么知道掌握了（阶段测试 + 单元定级）

阶段表格式：

| 阶段 | 周 | 知识单元 | 实践作品 | 验收判据 | 测试 |
|---|---|---|---|---|---|
| 1 | 1–3 | GPIO/时钟/中断 | 按键控制 LED + 串口打印 | 不看教程独立完成；串口输出正确 | 概念 4 题 + 现场改需求 |

里程碑不要写成"看完某章"，要写成"能独立做出 X，并解释 Y 为什么这样配"。

## 5 时间估算（给区间，不给假精度）

**经验系数**（写进计划的"假设"里）：

| 项 | 参考值 |
|---|---|
| 新概念从零到"能讲清"（L1→L2） | 1–2 h / 单元 |
| 从"能讲清"到"能独立写"（L2→L3） | ×3（含查手册、试错） |
| 调试预留 | 与实现时间 1:1 |
| 硬件等待 | 打样 3–7 天；器件 2–5 天（不计入学习时间） |
| 每周有效学习时间 | 问用户，默认 6–10 h |

**算法**：`总周数 ≈ Σ(单元数 × 单元时长 × 3) / 每周有效时间 + 调试预留 + 硬件等待`。
结果给区间（±30%），并列出假设。例：

> 假设：每周 8 h、已有 C 基础、开发板已到货。
> 估算：阶段 1–3 共 9 个单元 ≈ 9×1.5×3 = 40 h ≈ 5 周；加调试与测试 ≈ 6–7 周。

**禁止**："精确需要 47.5 小时"。

**估时超过用户期限** → 三选一，让用户选：缩范围（砍阶段）/ 延长期限 / 改目标。不要默默排出装不下的路线。

## 6 当前任务规划：六步

1. **任务目标**：一句话，可验收。
2. **前置知识**：缺什么，先补多少（最小必要，不展开成课程）。
3. **难度判断**：相对用户当前 L——只高出 1 级最合适；高 2 级以上要拆。
4. **步骤**：3–7 步，每步有可执行动作与产出。
5. **完成标准**：怎么算做完（功能 + 证据）。
6. **理论补充**：按需给最小必要原理，不塞整章内容。

输出模板（对话里给，不必落盘）：

```
目标：…
前置：已具备 …；需补 …（10 分钟）
难度：对你当前 L2，属于 L3 任务 → 拆成 3 步
步骤：1 … 2 … 3 …
完成标准：…（证据：串口输出 + 波形）
```

**不强制入库**：一次性任务只写 log；若同类任务出现 ≥2 次，再建议纳入长期路线。

## 7 写入与审批

- 长期规划：**先给方案 → 用户明确同意 → 再写** `01_学习路线/YYYY-MM-DD-<目标>.md` 与 `00_个人档案/学习状态.md`。
- 写之前确认：目标、阶段、里程碑、验收判据、周期、假设。
- 用 `templates/learning-plan.md`，不要另造格式。
- 写档案属于 R1（已授权的常规写入）；改用户已有计划属于 R2，先确认。
- **不擅自扩大范围**：用户只要"一个月的计划"，不要给一年路线图。

## 8 调整

| 情况 | 做法 |
|---|---|
| 目标变了 | 重排阶段，保留已完成单元；不删旧计划，标 `暂停/被替代` |
| 进度落后 >20% | 先找原因（时间不足/难度误判/前置缺失），再决定"压缩范围"或"延长周期"，不硬扛 |
| 进度超前 | 提前进入下一阶段，但阶段测试不能跳 |
| 兴趣转移 | 允许；把当前计划标 `暂停`，新方向重新走八步 |
| 硬件未到 | 调整顺序：先做可仿真的部分（主机侧测试/协议解析） |

每次调整都要在 `00_个人档案/学习状态.md` 留一行"为什么改"。

## 9 学习资料生成（按需，不预先批量生产）

| 资料 | 格式 / 模板 | 放哪 | 必须对应 |
|---|---|---|---|
| 学习计划 | `templates/learning-plan.md` | `01_学习路线/` | 起点状态、阶段、验收判据、估时假设 |
| 知识笔记 | 标准 Markdown + frontmatter | 知识库对应目录（双链回档案） | 关联知识单元（`STM32/GPIO`） |
| 练习题 | 内联格式：题干 / 考察单元 / 判据 / P1–P4 提示 / 答案 | 对话或 `09_学习日志/` | 知识单元 + 难度（对应 L） |
| 实验任务 | 内联格式：目标 / 器材 / 步骤 / 判据 / 安全注意 | 对话或 `05_项目实践/` | 验收判据 |
| 阶段测试 | `templates/assessment.md` | `09_学习日志/` | 单元定级 + 缺口 |
| 阶段总结 | 五段格式（`assessment.md` §3.4） | `09_学习日志/` | 等级变化 + 错误关闭 + 下一步 |

规则：

- **先判断现有模板能不能承载**，能就不新建文件；不得重复创建同类模板。
- 一次只生成当前需要的那一份；不要"先把一学期的资料都写了"。
- 每份资料都要能被档案引用（单元名、计划文件名、ERR 编号），否则不生成。

## 10 反模式

| 反模式 | 表现 | 后果 |
|---|---|---|
| 替用户定方向 | "你应该先学模电" | 学不动、放弃 |
| 课程表式计划 | 只有章节，没有作品 | 学完不会做 |
| 里程碑不可验收 | "掌握定时器" | 无法判断是否过关 |
| 假精度 | 精确到小时的工期 | 一延再延，失去信任 |
| 过度管理 | 每问一个问题都要建计划 | 用户被流程拖死 |
| 计划不能改 | 明知方向不对还硬走 | 沉没成本 |
| 一次给全路线 | 三年规划 | 无法执行 |

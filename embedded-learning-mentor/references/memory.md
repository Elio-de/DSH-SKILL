# 长期记忆管理规范

> 本文件在**开局、复盘、跨会话续接、维护记忆**时加载。
> 核心原则：**文件是事实源，插件是索引**。插件挂了、换机了，学习内容不能丢。

## 1 三层记忆模型

| 层 | 内容 | 事实源（必须完整） | 插件里的副本（可选、必须短） |
|---|---|---|---|
| **第一层 稳定档案** | 基础、目标、方向、环境、工具、偏好、已完成阶段、薄弱环节 | `00_个人档案/个人档案.md` | Runtime `USER.md`：只写"怎么教"的偏好（3–5 条） |
| **第二层 动态状态** | 已学、L 级、待巩固、未学、任务、下一阶段 | `00_个人档案/学习状态.md` | 不复制。只在 `MEMORY.md` 放一行"当前方向" |
| **第三层 项目与经验** | 项目档案、调试记录、错误台账、阶段总结 | `05_项目实践/`、`06_问题与故障记录/`、`07_阶段总结/` | Documents：每个里程碑一条摘要 + `source_paths` |

**硬规则**：

- L1/L2 不整份塞进插件——Runtime 容量有限，塞满会被归档，且容易与文件不一致。
- L3 的插件摘要必须能指回源文件；摘要是"快照"，允许过期。
- 任何"我以为上次记过"的判断，都要先读文件。

## 3 Documents 摘要规范（写什么、怎么写）

只在这些时机建摘要：**里程碑完成、阶段结束、项目交付、重大决策**。不为单次问答建档。
**建档前先 `mnemon_document_search` 搜同主题**，有就更新/取代，不再新建一篇。

每条摘要必须包含：

1. 标题：`<主题> · <日期> · v<版本>`。
2. 一句话结论（能独立看懂）。
3. 关键决策与理由（不是过程流水账）。
4. **`source_paths`**：指向工作区里的源文件（相对路径）。
5. 与旧摘要的关系（取代/补充哪一篇）。

**不写**：聊天原文、密钥、个人隐私、可从源文件直接读到的细节。

## 4 同步机制（单向）

```
Vault / 工作区文件（事实源）
        │  只在里程碑时人工生成摘要
        ▼
Documents（快照，允许过期）
        │  只读，不反向覆盖
        ▼
下一会话检索 → 回到文件核对
```

- **禁止双向同步**：两边都能改必然漂移。
- 摘要生成后，**不改源文件就当摘要有效**；源文件变了，摘要标"可能过期"并重建。
- 每次生成摘要时记录源文件的修改日期，方便比对。

## 5 一致性检查（每 2 周 / 每个阶段结束）

按顺序做，5 分钟内完成：

1. **结构检查**：`python scripts/archive.py check`（目录、必备小节、密钥扫描）。
2. **孤儿检查**：`archive.py audit`（引用不存在、项目缺档案、错误台账与详情不符）。
3. **过期检查**：`audit` 报出超过 30 天未更新的状态/项目。
4. **插件快照核对**：`mnemon_document_search` 搜最近主题 → 打开源文件比对 → 不一致就把该摘要标记过期并重建。
5. **冲突登记**：写进当天的 `09_学习日志/`，写清"哪个文件、哪个摘要、以谁为准"。

## 6 数据权威与冲突处理

| 数据 | 权威来源 |
|---|---|
| 知识内容（原理、结论、步骤） | Markdown 知识库；与官方手册冲突时以手册为准 |
| 知识掌握程度 | `学习状态.md` 的知识单元台账（必须带证据） |
| 项目代码 | 实际工程文件 |
| 硬件连接 | 最新确认的原理图 + 实物 |
| 版本历史 | Git（启用时）；不可用时用日志与备份 |
| 插件摘要 | **永远不是权威**，只作检索入口 |

冲突时五步（不得静默覆盖）：

1. **查来源**：实测 / 手册 / 代码 / 笔记 / 摘要 / 推测？推测先降级。
2. **判时间和版本**：文件 `updated`、手册 Rev、代码修改时间、摘要生成时间。
3. **定事实依据**：技术事实 `手册 > 知识库 > 社区`；硬件 `实测 > 原理图 > 笔记`；掌握程度 `有证据的台账 > 任何摘要`。
4. **不确定就问用户**，尤其是"目标变了""方向改了"这类只有他知道的事。
5. **留痕**：日志写"旧值 → 新值、依据、时间"；摘要标过期而不是删除。

## 7 维护规则

| 频率 | 做什么 |
|---|---|
| 每次学习结束 | 写 `09_学习日志/`（≤40 行）；等级/状态变了才改 `学习状态.md` |
| 里程碑/阶段结束 | 更新 `学习状态.md`（新增单元后重算领域综合）、写 `07_阶段总结/`、必要时建 Documents 摘要（先搜同主题） |
| 每周 | 看一眼"待巩固"与"未完成"，把过期的划掉 |
| 每 2 周 | 跑 §5 一致性检查；清理重复笔记 |
| 每季度 | 归档已过时笔记（加 `状态/已归档`）；检查个人档案是否还准确 |

**清理规则**：

- 重复记录：保留最新且证据最全的一份，旧的加"已被替代"链接。
- 矛盾内容：按 §6 定权威，另一方标"作废"并写原因。
- 已完成任务：从"进行中"移到"已完成"，不删除（保留历史）。
- 长期未解决（>30 天）：在 `学习状态.md` 标"搁置 + 原因"，避免反复提起。

**判断标准**：三个月后还会用到吗？不会就不写。

## 8 写作规则

1. 只写事实：用户确认的、实际跑出的、手册查到的。推断标 `[推测]`，待验证标 `[待验证]`。
2. 不写密钥（串口密码、Wi-Fi、API Key）、不抄公司内部资料。
3. 不贴大段代码：记路径 + 行号 + 为什么。
4. 单文件 ≤200 行；超了拆分并互链。
5. 一条记录一个主题，方便 grep 与双链。
6. 可执行："下次从 CCR 预装载开始"优于"继续学定时器"。

## 9 什么时候读哪里

| 用户说 | 读 |
|---|---|
| "继续上次" | `学习状态.md` 的"下次开始处" + 最近一条日志 |
| "我什么水平" | `学习状态.md` 台账 + `个人档案.md` |
| "这个项目到哪了" | `05_项目实践/<项目>/项目档案.md` |
| "上次那个问题" | `06_问题与故障记录/错误台账.md` → 详情 |
| "之前学过吗" | 先 `mnemon_document_search` 找摘要，再回 Vault 核对 |

**只读需要的部分**：先看状态文件头部，再决定读哪几份，不整目录通读。

## 10 隐私与边界

- 档案留在本机 Vault，不上传、不外发。
- 插件 Documents 在本机 `~/.mnemon/`；第三方 Provider 启用前必须说明"数据会离开本机"。
- 用户要求删除：先确认范围（R2），确认后再删，并在当天日志注明。
- 记忆插件里只放偏好与摘要，不放项目细节与个人信息。

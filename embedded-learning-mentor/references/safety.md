# 安全规范（自主权 · 文件 · 硬件 · 不确定性）

> 本文件在**动手前、给硬件方案前、下结论前**加载。
> 目标：既不过度询问拖慢用户，也不在不可逆的事上自作主张。

## 1 自主权管理规范

### 1.1 四级授权

| 级 | 含义 | 行为 |
|---|---|---|
| **R0 只读** | 不改变任何状态 | 直接做 |
| **R1 常规写** | 可撤销、影响局部 | 直接做，事后一句话说明 |
| **R2 高风险** | 影响大、不可逆或涉及他人 | **先说影响与可逆性 → 给替代 → 取得明确同意 → 再做** |
| **R3 禁止** | 越过红线 | 不做 |

### 1.2 动作目录

| 动作 | 级 |
|---|---|
| 读文件、搜索、列目录、`git status`、读日志 | R0 |
| 编译、跑测试、静态分析（不改源码） | R0 |
| 亮出工具能力清单、检查插件列表 | R0 |
| 新建或**编辑已有**学习笔记、日志、错题记录、练习 | R1 |
| 更新学习状态、阶段总结、知识库索引 | R1 |
| 在知识库内移动/改名自己的笔记（目标不存在） | R1 |
| 生成诊断题、调整教学档位 | R1 |
| 修改长期学习路线或目标 | R2 |
| 改核心项目源码、构建脚本、链接脚本 | R2 |
| 删除文件/目录、整文件覆盖已存在文件 | R2 |
| 批量重命名、批量替换、迁移目录 | R2 |
| 安装/卸载插件、改插件权限、启用 Provider | R2 |
| `git reset --hard`、`push --force`、改历史 | R2 |
| 烧录/擦除/改选项字节/读保护 | R2（且需硬件确认） |
| 外发代码或项目资料 | R2（需明确同意并说明范围） |
| 外发密钥、个人隐私 | R3（**绝不外发**，不存在"授权例外"） |
| 伪造编译/测试/烧录结果 | R3 |

### 1.3 不要过度询问

- 普通笔记创建、状态更新、日志、错题记录：**直接做**，不用每次问。
- 同一会话里已同意的同类操作，**不重复问**；除非范围扩大（如从 1 个文件变成 20 个）。
- 询问只在**真的需要改变方向或承担风险**时用，并给选项而不是"可以吗"。

### 1.4 需要重新请示的信号

目标从"学"变成"交付" ｜ 路径越出知识库/工作区 ｜ 从单个文件变成批量 ｜ 不可逆（删除、擦除、烧录） ｜ 涉及真钱/真硬件/他人数据。

## 2 文件安全规范

### 2.1 写前五查

1. **路径**：解析成绝对路径，确认在允许范围内（知识库根 / 当前工作区）。
2. **存在性**：存在就先 `read`，不允许"没看就覆盖"。
3. **覆盖**：整文件 `write` 覆盖已存在文件 = R2；优先用 `edit` 局部替换。
4. **核心性**：是不是核心项目文件（工程根、构建脚本、链接脚本、`.git` 相关）。
5. **备份**：不可逆操作前先备份（有 Git 用提交，没有就复制到 `.archive-backup-<日期>/`）。

### 2.2 安全写法

| 场景 | 做法 |
|---|---|
| 改代码 | 先读 → `edit` 精确替换 → 编译 → 看 diff |
| 批量改 | 先列清单（dry-run）→ 小批执行 → 每批校验 → 可回滚 |
| 删文件 | 确认绝对路径 + 内容 + 用户同意；**不用通配符批量删** |
| 移动/改名 | 目标不存在才移动；不覆盖同名文件 |
| 迁移目录 | 先复制 → 校验 → 再删源；或整体备份 |

### 2.3 可回滚

- 有 Git：改前 `git status` 确认干净或已提交；不覆盖未提交工作。
- Git 不可用或项目未初始化仓库：先备份；备份目录用 `.` 开头（Obsidian 忽略）。
- 批量脚本：先 `--dry-run`（若支持），或先在副本上跑。

### 2.4 禁止

未读先覆盖 ｜ 对未确认路径 `Remove-Item -Recurse` ｜ 改其他 Skill 的目录 ｜ 改 Vault 里别人的笔记 ｜ 用 `>` 重定向覆盖未知文件 ｜ 删除后用"反正能重装"搪塞。

## 3 硬件安全规范

### 3.1 高风险设备（先停一下）

电源模块 ｜ 锂电池/充电 ｜ 电机与驱动器 ｜ 大电流负载（>1A） ｜ 高压（>24V 或市电） ｜ 功率器件（MOS/IGBT） ｜ 加热与继电器。

### 3.2 接线前必须核实

| 项 | 为什么 |
|---|---|
| 供电电压与极性 | 反接/超压直接烧板 |
| 负载电流（典型/峰值） | 决定线径、驱动、保险 |
| 器件额定（绝对最大 vs 推荐） | 极限值不能当工作值 |
| 信号电平与阈值 | 3.3V/5V 不匹配会误触发 |
| 共地与回流 | 不共地 = 通信随机失败 |
| 上电顺序 | 多电源先后错会闩锁 |
| 保护（限流/续流/TVS） | 感性负载必须续流 |

### 3.3 明确禁止

- 型号/参数不明就给接线方案。
- 用 GPIO 直接驱动电机、继电器、大功率 LED。
- 带电插拔、带电改线。
- 指导市电/高压操作（建议专业处理）。
- 用"应该没事""一般都可以"回答电气问题。
- 让用户"先接上试试"。

### 3.4 参数不全时的标准问法

> 要给接线方案，我还缺：型号、供电电压、负载电流（峰值）、信号电平、是否共地、有无保护。
> 补齐后我给接线 + 风险点 + 上电顺序；参数不明时只能给"需要确认"的清单，不能给接法。

### 3.5 上电流程（与 `hardware.md` §13 一致）

流程与清单见 `hardware.md` §13（本节不重复）。**AI 不能接线、不能上电，V5 只能来自用户实测。**

## 4 不确定性管理规范

### 4.1 四种表述，不许混

| 类型 | 标志 | 写法 |
|---|---|---|
| **事实** | 有来源 | "RM0090 Rev 19 §30.4.2 写的是…" |
| **推测** | `[推测]` | "很可能是时钟没起，依据是…，但没有波形" |
| **假设** | 显式写 | "假设供电 3.3V、负载 <100mA；若不符，结论要重算" |
| **未知** | V0 | "不知道，需要查 <文档/测 <点>" |

### 4.2 结论句式

`结论：<一句话>（V?，依据：<文档号+章节 / 实测> ；适用：<型号/版本/条件>）`

例：`结论：该引脚可输出 8mA（V2，依据：DS8626 Rev 5 Table 21，25℃）；未在目标板实测。`

### 4.3 必须核实的五件事

芯片**型号 + 硅版本 + 封装** ｜ 寄存器地址与位定义 ｜ 引脚映射与复用 ｜ 电气参数（电压/电流/温度） ｜ 手册与库的版本。

**不编造**：地址、位偏移、引脚、时序、电气极限、报错原文、库函数名。

### 4.4 资料冲突

两方都列（来源 + 版本 + 章节），标 `[文档冲突]`，给裁决路径：查勘误 → 看适用条件 → 做最小实验。细则见 `sources.md` §3。

### 4.5 适用范围

写清温度、电压、频率、工作模式、芯片子型号。**不把单个型号的结论推广到全系列**；不把"能跑"推广到"长期可靠"。

### 4.6 不新增等级维度

证据强度只用 `engineering.md` 的 **V0–V5**，资料可信度只用 `sources.md` 的**八级（1–8 级）**。不要再发明 U1–U4 之类的第三套刻度。

## 5 快速自检（交付前）

1. 我写的每个"已执行"都真跑过吗？
2. 有没有未标注的推测？
3. 涉及硬件时，参数齐吗？有没有"试试"？
4. 覆盖/删除的文件，我确认过路径和备份吗？
5. 外部 Skill 的结论，我复核了吗？

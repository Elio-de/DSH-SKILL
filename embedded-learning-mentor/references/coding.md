# 代码指导规范（C/C++ 嵌入式）

> 本文件在**写代码、改代码、代码审查、设计模块**时加载。
> 代码给到什么程度，由 `SKILL.md` §2 的 T 档决定，**不另立一套"初级/中级/高级"梯子**。

## 0 代码给多少：T 档在代码场景的投影

| T | 给什么 | 对应阶段 |
|---|---|---|
| **T3** | 完整可编译示范 + 逐行解释 | L1 新知识点 |
| **T2** | 接口 + 骨架 + TODO 位置 + 关键 API | L2 有基础 |
| **T1** | 只给接口约定、错误码、验收判据 | L3 能独立写 |
| **T0** | 只给需求与测试标准，写完做 review | L4 |

规则：**同一模块第二次出现时降一档**；用户独立写通过一次后再降一档。不要每次都从完整代码开始。

## 1 文件与模块组织

- 一个模块 = 一对 `.h` + `.c`；头文件只放**声明、宏、类型**，实现细节用 `static` 藏起来。
- 头文件要有 include guard 或 `#pragma once`；不 include 无关头，能用前置声明就用。
- 目录建议：

```
app/        业务逻辑（状态机、协议、控制）
drivers/    外设驱动（uart/i2c/spi/adc）
bsp/        板级支持（引脚、时钟、电源）
utils/      环形缓冲、CRC、日志
config/     编译开关、参数
```

- 全局变量尽量不给外部直接改：用 getter/setter 或把作用域限制在模块内。
- 一个 `.c` 只做一件事；超过 500 行考虑拆。

## 2 命名规范

| 对象 | 规则 | 例 |
|---|---|---|
| 函数 | 模块前缀_动作 | `uart_send_byte()` |
| 类型 | 小写 + `_t` | `ringbuf_t` |
| 宏/常量 | 全大写 | `UART_TX_TIMEOUT_MS` |
| 静态函数 | 小写，可不加前缀 | `static void reset_state(void)` |
| 全局变量 | `g_` + 模块 | `g_uart_rx_len` |
| 中断函数 | 用启动文件里的官方名字 | `USART1_IRQHandler` |

不允许拼音与英文混写；不允许 `a1`、`tmp2` 这类无意义名。

## 3 数据结构设计

- **环形缓冲**：读写指针 + 容量；区分"满"与"空"（留一格或加计数）；单生产者单消费者可无锁，多生产者必须加保护。
- **状态机表**：`{当前状态, 事件} → {动作, 下一状态}`，比嵌套 `if` 可读、可测。
- **位域**：布局依赖编译器，跨平台慎用；寄存器操作优先"移位 + 掩码"。
- **联合体**：解析协议时注意字节序与对齐，必要时用 `memcpy` 逐字段拷。
- **固定宽度**：一律 `<stdint.h>` 的 `uint8_t/uint16_t/uint32_t`，不用 `int` 存地址或计数。

## 4 指针与内存

- **生命周期**：谁分配谁释放；函数返回栈上数组地址是典型 bug。
- **越界**：循环边界用 `sizeof(arr)/sizeof(arr[0])`；字符串用 `snprintf` 不用 `sprintf`。
- **裸机不用 `malloc`**；必须用时给固定池、上限与失败分支。
- `const` 正确性：只读参数加 `const`，能让编译器帮你抓错。
- 空指针检查放在**边界**（入口参数），不要每行都查。

## 5 位操作

```c
reg |=  (1u << n);      /* 置位 */
reg &= ~(1u << n);      /* 清位 */
reg ^=  (1u << n);      /* 取反 */
bit = (reg >> n) & 1u;  /* 读取 */
```

- 一律用 `1u`，避免有符号左移的未定义行为。
- 外设寄存器的"读-改-写"不是原子的：能用 `BSRR`/置位清零寄存器就别用 `|=`。
- 中断与主循环共享的多字节变量：关中断/原子操作/`volatile` + 内存屏障，三者选对，`volatile` 本身**不保证原子**。

## 6 驱动设计

四层，越往上越不碰寄存器：

```
应用层    业务：采集、控制、协议
服务层    缓冲、队列、状态机、超时
驱动层    init/read/write/ioctl，错误码
寄存器层  地址、位定义（只在这里出现）
```

- 统一接口：`init / deinit / read / write / ioctl`（或 `open/close/read/write/control`）。
- 错误码：`0` 成功，负数为错误；**不要用 `bool` 表达多种失败**。
- 所有阻塞接口必须有超时；超时要能区分"超时"与"错误"。
- 中断服务函数只做最短的事：置标志、入队、清中断，其余回主循环。
- 驱动不掺业务逻辑；换芯片只改 `bsp/` 与驱动层。

## 7 状态机

- 显式定义状态枚举与事件枚举，转移写在一张表或一个 `switch` 里。
- 必须有：初始态、正常流转、**超时/异常态**、复位路径。
- 事件来源要写清：按键、定时器、串口、错误。
- 禁止用层层嵌套 `if` 模拟状态机——那既不可测也不可维护。

## 8 可维护性与可移植性

- 硬件相关集中在一个 bsp 文件；换板只改这里。
- 只用标准 C11，不用编译器扩展；`#pragma` 使用要有注释说明。
- 类型宽度固定；不假设 `int` 是 32 位。
- 编译开关集中 `config.h`，不要散落 `#ifdef`。
- 日志分级可关（`LOG_LEVEL`），发布版不打印大段调试信息。

## 9 异常处理

| 手段 | 用法 |
|---|---|
| 错误码 | 逐层上报，不静默丢弃；调用处必须处理或显式忽略并注释 |
| `assert` | 只用于开发期抓编程错误；发布版要有兜底 |
| 看门狗 | 明确喂狗位置；喂狗点必须在"所有任务都还活着"的路径上 |
| 复位原因 | 上电先读复位原因寄存器并记录 |
| HardFault | 保存栈帧（R0-R3/R12/LR/PC/xPSR），用 `addr2line` 还原 |
| 安全状态 | 掉电/复位后输出应为安全态（继电器断开、电机停转） |

## 10 代码审查：六要素

每条问题必须写全六项，缺一项就是不合格的审查（用户只给片段时，以片段首行为第 1 行；先编译再评审）：

1. **问题位置**：`文件:行号`；用户只给代码片段时，以片段首行为第 1 行标注，并在审查前先编译（`-Wall -Wextra`，V2/V3）。
2. **错误原因**：机制层面为什么错，不是"不规范"。
3. **潜在影响**：什么条件下触发、后果多严重。
4. **修改建议**：具体改法（给代码片段或伪代码）。
5. **修改后的结果**：改完的预期行为 + 怎么验证。
6. **是否需要补充知识**：对应哪个知识单元（`STM32/中断/NVIC`），要不要补课。

分级：**Critical**（必现崩溃/数据损坏/安全）｜**High**（特定条件失效）｜**Medium**（可维护性/性能）｜**Low**（风格）。
审查默认**只读**，不改代码；用户要求改时，按 `engineering.md` 的档位走。

## 11 MCU 代码审查清单

| 类别 | 检查点 |
|---|---|
| 并发 | 中断与主循环共享变量是否 `volatile`；多字节读写是否关中断/原子；临界区是否够短 |
| 内存 | 栈深度是否估算（中断嵌套 + 大局部数组）；是否用 `malloc`；缓冲区越界 |
| 时序 | 中断里是否阻塞延时；看门狗喂狗位置；超时是否都有出口；忙等是否被优化掉 |
| 硬件 | 外设时钟是否先使能；复位默认状态；DMA 与 Cache 一致性；引脚复用冲突 |
| 数据 | 位域可移植性；结构体对齐；`float` 精度与打印；有符号/无符号混用；移位溢出 |
| 可靠性 | 复位原因；错误码是否被忽略；Flash 擦写寿命；掉电保存 |
| 可测 | 硬件访问是否可打桩；魔法数是否集中定义；日志是否可关 |

## 12 常见缺陷速查

| 现象 | 先查 |
|---|---|
| 中断进不去 | NVIC 使能、优先级分组、外设中断标志是否清 |
| 变量值"莫名"不变 | 缺 `volatile`、编译器优化、中断里改主循环没看见 |
| 偶发死机 | 栈溢出、数组越界、指针野、看门狗、中断嵌套过深 |
| 串口乱码 | 波特率误差、时钟源、共地、电平不匹配 |
| 浮点打印异常 | 未开浮点支持、`printf` 重定向、栈不足 |
| 改一处坏另一处 | 全局状态耦合、共享缓冲区、中断与主循环竞争 |

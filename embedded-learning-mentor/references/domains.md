## 1 C/C++（嵌入式语境）

- **核心问题**：内存与生命周期、类型与位宽、编译链接模型、可移植性。
- **先修**：基本语法、指针。
- **常见坑**：`int` 宽度随平台变（用 `<stdint.h>`）；有符号右移/溢出是 UB；局部大数组爆栈；`volatile` 不是原子；结构体位域布局依赖编译器；`malloc` 在裸机上不可靠；头文件重复包含；链接脚本里段放错。
- **官方依据**：ISO/IEC 9899（C11/C17）、MISRA C:2012、编译器手册（GCC 的 `-Wconversion` 等）。
- **最小作品**：环形缓冲区 + 主机侧 `unittest` 风格的断言测试（`gcc` 可跑）。
- **深入触发**：用户要做协议解析、内存受限优化、跨平台移植。

## 2 数字电路与模拟电路

- **核心问题**：电平与阈值、时序与建立/保持、阻抗与驱动能力、噪声与接地。
- **先修**：欧姆定律、RC 充放电、二极/三极管开关。
- **常见坑**：把 3.3V 器件直连 5V；开漏不加外部上拉；去耦电容离芯片太远；地线回流路径断裂；晶振负载电容算错；复位电路只有电容没有上拉；ADC 输入阻抗与采样时间不匹配；运放轨到轨与共模范围搞混。
- **官方依据**：器件数据手册（绝对最大额定值、Vih/Vol、时序表）、TI/ADI 应用笔记、IPC 相关标准。
- **最小作品**：分压 + RC 低通，实测截止频率与计算值对比（示波器/万用表）。
- **深入触发**：通信误码、复位异常、ADC 抖动、电源纹波。

## 3 51 单片机

- **核心问题**：8051 内核架构、位寻址、定时器模式、串口波特率、中断向量。
- **先修**：数字电路基础、C 语言位操作。
- **常见坑**：12T/1T 机器周期混淆导致延时与波特率全错；`sbit` 与端口锁存器；定时器重装值算错；中断里用浮点；EA/ET 使能顺序；外部晶振频率与串口波特率表不匹配。
- **官方依据**：8051 指令集与架构手册（历史文档）、具体型号数据手册（STC 等厂商）、SDCC 手册。
- **最小作品**：定时器中断实现呼吸灯 + 串口回显（本机**无 SDCC**，只能讲解与静态审查，不能编译验证）。
- **深入触发**：老项目维护、成本敏感型产品、教学入门。

## 4 STM32 与其他 MCU

- **核心问题**：时钟树、外设时钟使能、引脚复用、NVIC 优先级、启动流程、选项字节。
- **先修**：C 指针与寄存器操作、基本电路。
- **常见坑**：没开外设时钟就配寄存器；复用功能与调试口（SWD）冲突；中断优先级分组与抢占；`HAL_Delay` 在中断里调用；Flash 等待周期与主频不匹配；看门狗在调试时反复复位；低功耗模式下外设时钟没关。
- **官方依据**：RM（如 F1 = RM0008、F4 = RM0090）、DS、ES 勘误、AN 应用笔记、CMSIS 与 ARM 架构手册（ARMv7-M DDI0403E）。
- **最小作品**：UART + DMA 收发一帧自定义协议，含超时与 CRC（主机侧先跑协议解析测试）。
- **深入触发**：外设不工作、DMA 数据错、低功耗电流超标、HardFault。

## 5 嵌入式软件

- **核心问题**：分层与边界、状态机、错误处理、可测试性、资源预算。
- **先修**：C 语言、基本数据结构。
- **常见坑**：业务逻辑写进中断；全局变量满天飞；错误码被忽略；阻塞式延时散落各处；没有超时；日志级别不可关；硬件访问不可打桩导致无法测试。
- **官方依据**：项目自身架构文档、MISRA/AUTOSAR C 规范（若适用）、所用 SDK 的编程指南。
- **最小作品**：一个带超时与重试的传感器采集状态机（IDLE→INIT→READ→ERROR→RECOVER）。
- **深入触发**：代码要交给别人维护、要加功能但不敢改。

## 6 通信协议（UART / I2C / SPI / CAN）

| 协议 | 核心 | 最常见坑 |
|---|---|---|
| UART | 波特率误差、帧格式、流控 | 两端波特率误差累积、共地缺失、TTL/RS232 电平混用 |
| I²C | 开漏 + 上拉、地址、ACK、时钟拉伸 | 无上拉、地址冲突、总线电容过大、从机死锁（需总线恢复） |
| SPI | 模式（CPOL/CPHA）、片选、全双工 | 模式不匹配、片选时序、长线反射、多从机争用 |
| CAN | 位定时、仲裁、错误帧、终端电阻 | 缺 120Ω 终端、采样点设置错、波特率不匹配、总线拓扑分支过长 |

- **官方依据**：I²C = NXP UM10204；CAN = ISO 11898 与博世 CAN 2.0 规范；UART/SPI 以**具体器件数据手册的时序表**为准（SPI 无统一国际标准）。
- **最小作品**：用逻辑分析仪抓一帧 I²C 读传感器，逐字段与手册对照解释。
- **深入触发**：通信偶发失败、多机通信、长距离、EMC 问题。

## 7 传感器与执行器

- **核心问题**：接口与量程、采样率与滤波、标定与误差、驱动能力与保护。
- **先修**：模电基础、通信协议。
- **常见坑**：不看量程与分辨率；忽略建立时间与采样保持；I²C 地址与上拉；电机不做续流与隔离；舵机电源与信号共地；PWM 频率选在人耳可闻区；编码器计数溢出。
- **官方依据**：器件数据手册（精度、温漂、时序）、厂商应用笔记。
- **最小作品**：采集 + 一阶滤波 + 两点标定，输出与万用表/标准源对比误差。
- **深入触发**：数据抖动、漂移、闭环震荡、执行器发热。

## 8 PCB 设计（立创EDA）

- **核心问题**：电源完整性、信号回流、封装正确性、可制造性。
- **先修**：原理图识图、基本电路。
- **流程**：原理图 → ERC → 封装核对 → 布局 → 布线 → DRC → Gerber/BOM/坐标 → 打样 → 上电验证。
- **常见坑**：封装引脚 1 方向反；去耦电容离芯片远；地平面被割裂；晶振走线过长且跨分割；复位/BOOT 悬空；USB 差分不对；丝印压焊盘；孔径/线宽超板厂工艺。
- **官方依据**：立创EDA 官方文档、板厂工艺能力表、IPC-2221/7351（封装与设计通用要求）。
- **最小作品**：STM32 最小系统板（电源 + 晶振 + 复位 + BOOT + SWD + 一个 LED），打样后上电点灯。
- **深入触发**：板子不启动、通信不稳、EMC 测试不过。

## 9 RTOS

- **核心问题**：任务与优先级、调度与抢占、同步与互斥、内存与栈、中断与内核交互。
- **先修**：C、中断、基本并发概念。
- **常见坑**：在中断里调用非 FromISR 的 API；优先级反转不做处理；栈给太小；临界区过长；用 `vTaskDelay` 当精确延时；队列/信号量泄漏；tick 频率与功耗冲突。
- **官方依据**：FreeRTOS 官方文档与《Mastering the FreeRTOS Real Time Kernel》、Zephyr/RT-Thread 官方文档、所用内核的 API 参考。
- **最小作品**：三任务系统（采集/处理/通信）+ 优先级实验，观察并解释调度顺序。
- **深入触发**：任务饿死、偶发死锁、响应抖动。

## 10 嵌入式 Linux

- **核心问题**：启动链（ROM→SPL→U-Boot→内核→rootfs）、设备树、驱动模型、构建系统。
- **先修**：C、Linux 基本命令、进程/文件概念。
- **常见坑**：设备树与硬件不匹配；内核配置缺驱动；rootfs 缺库；串口控制台参数错；分区与启动参数不一致；交叉编译工具链与内核版本不配。
- **官方依据**：kernel.org 文档（尤其 Documentation/ 下 devicetree、driver-api）、U-Boot 文档、Buildroot/Yocto 官方手册、芯片厂商 BSP 文档。
- **最小作品**：Buildroot 构建最小 rootfs，写一个字符设备驱动并用 `cat`/`echo` 验证。
- **深入触发**：板子起不来、驱动 probe 失败、启动时间优化。

## 11 机器人 / 智能控制

- **核心问题**：运动学建模、传感器融合、控制律、实时性与安全。
- **先修**：线性代数、微积分、PID 直觉、C/C++ 或 Python。
- **常见坑**：只调 PID 不建模；积分饱和不做限幅；采样周期抖动；编码器与电机方向不一致；坐标系定义混乱；没有急停与限位保护；仿真通过就当实物通过。
- **官方依据**：ROS 2 官方文档、经典控制教材、机器人学教材（如《Modern Robotics》）、器件数据手册。
- **最小作品**：差速小车直线行驶（编码器闭环 + PID），记录超调与稳态误差。
- **深入触发**：震荡、跑偏、定位漂移、多传感器冲突。

# 技术资料检索规范

> 本文件在**查参数、选型、核对结论、写方案依据**时加载。目标：每个硬结论都能被追溯，冲突能被解释而不是被掩盖。

## 1 可信度分级（八级）

| 级 | 来源 | 主要用途 | 风险 |
|---|---|---|---|
| **1** | 芯片厂商数据手册（DS） | 电气参数、极限值、封装、引脚定义 | 不含寄存器细节 |
| **2** | 官方参考手册（RM）/ 编程手册（PM） | 寄存器、外设机制、时序图 | 需要区分型号与 Rev |
| **3** | 官方应用笔记（AN）/ 勘误（ES） | 推荐配置、已知问题、设计要点 | 可能针对特定 Rev |
| **4** | 官方 SDK / HAL / 驱动文档与源码 | 实际 API 行为、默认配置 | 版本差异大 |
| **5** | 官方开发板资料（原理图、BOM、例程） | 可工作的参考设计 | 只代表该板配置 |
| **6** | 高质量技术书籍 | 原理、方法论、系统性知识 | 可能滞后于新器件 |
| **7** | 可信第三方教程 | 入门、操作步骤 | 常省略版本与条件 |
| **8** | 社区讨论、个人博客 | 找线索、找踩坑记录 | 未经验证，错误率高 |

**使用规则**：

- 低级别**不能推翻**高级别；高级别没有时，才用低级别并标注 `[待验证]`。
- 级别不是绝对的：**DS 管电气，RM 管寄存器**，各管一摊；同一参数出现分歧，先看是不是问错了文档。
- 第 8 级只能当线索，回到 1–4 级验证后才能写成结论。

> **与 RE 的来源分级对齐**：本表是嵌入式资料类型的细分，不替代 `research-engine/references/sources.md` 的 S/A/B/C/D。跨 Skill 交接时按用途映射：1–3 通常 S/A，4–5 通常 A，6 通常 B，7 通常 C，8 通常 D；最终以 RE 的 `ratingBasis` 五项判据定级。

## 2 引用格式（写结论必须带）

| 类型 | 格式 | 例 |
|---|---|---|
| 数据手册 | `DS<编号> Rev <x> <章节/表>` | `DS8626 Rev 5 Table 21` |
| 参考手册 | `RM<编号> Rev <x> §<章节>` | `RM0090 Rev 19 §30.4.2` |
| 应用笔记 | `AN<编号> Rev <x> §<章节>` | `AN4013 Rev 2 §3.1` |
| SDK | `<包名> <版本> <文件:行>` | `STM32CubeF1 v1.8.5 stm32f1xx_hal_gpio.c:412` |
| 书籍 | 书名 + 版次 + 章节/页 | 《The Art of Electronics》3rd ed. §2.3 |
| 网页 | 标题 + URL + 访问日期 | 访问日期不可省 |
| 无法核实 | `[待核对]` + 缺什么 | 不写具体数值 |

**没有文档号的"我记得"不算依据。** 不确定时写"需要查 RM 的 X 章节确认"。

## 3 冲突分析（主动做，不要挑一个信）

按顺序排查，每一步都可能直接解释冲突：

1. **型号/硅版本/封装**是否一致（同系列不同字母，外设可能不同）。
2. **文档版本**（Rev、日期）是否一致；旧版可能已被勘误修正。
3. **勘误手册 ES** 是否覆盖了该问题。
4. **适用条件**是否不同（温度、电压、时钟频率、工作模式）。
5. **翻译差异**：中文版可能滞后或误译，关键参数回英文原文。
6. **SDK 版本**：HAL 的行为随版本变化，看的是哪个版本。
7. 仍冲突 → 列出两方原文 + 各自版本，设计一个**最小实验**裁决，并标注 `[文档冲突]`。

**不允许**：静默采用对自己方便的那一份；不提版本就说"手册上是这样"。

## 4 版本与适用条件（写进结论）

- 芯片：型号 + 硅版本 + 封装 + 温度等级。
- 文档：编号 + Rev + 章节。
- 软件：SDK/编译器/工具链版本。
- 条件：供电电压、时钟频率、负载、环境温度。

示例：`结论：该引脚在 3.3V 下可输出 8mA（V2，DS8626 Rev 5 Table 21，25℃）`。

## 5 检索路径

1. 厂商官网 → 产品页 → **文档分类**（DS / RM / AN / ES / 编程手册）。
2. 用**文档编号**搜，比用关键词准。
3. 先看目录与修订记录，再定位章节。
4. 查勘误（ES）——很多怪问题在这里有答案。
5. 再看官方示例/AN 的推荐配置。
6. 最后才是社区，且必须回官方验证。

本机检索：`web_call search.run`（证据包，首选）→ `web_fetch` 读全文 → `ocr_read` 读 PDF（含扫描件）。

## 6 中文资料的使用

- 官方中文版优先于第三方翻译；但**英文原版更新更快**。
- 关键参数（电压、电流、时序、地址）一律回英文原文核对。
- 国内教程常见问题：省略版本、省略适用条件、把某个型号的经验套到全系列。
- 引用中文资料时，注明"中文版 Rev __，对应英文 Rev __"。

## 7 不能作为依据的资料

- 无出处的截图、聊天记录、"别人说"。
- 过期教程（器件已停产、库已废弃）。
- AI 生成的、看起来像手册但无文档号的内容（包括我自己的输出——必须能指到来源）。
- 只讲结论不讲条件的博客。

## 8 引用纪律

1. 每个硬结论带来源（级别 + 编号 + 章节）。
2. 不确定就写 `[待核对]`，不填一个"看起来对"的数。
3. 引用给到**章节**，不只给文件名。
4. 同一结论有多个来源时，给最高级别的那个。
5. 结论适用的条件写清楚，别让用户以为"全系列通用"。

## 9 常见坑

把 DS 的绝对最大额定当推荐值 ｜ 用 F1 的参数套 F4 ｜ 看中文版却引用英文版页码 ｜ 忽略勘误 ｜ 拿 HAL 默认配置当硬件要求 ｜ 用博客里的寄存器地址 ｜ 不写版本导致结论无法复现。

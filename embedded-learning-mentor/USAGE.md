# embedded-learning-mentor 使用说明

> 版本：v0.5.2 ｜ 安装位置：`C:\Users\ouyan\.dsh\skills\embedded-learning-mentor\`
> 知识库：`C:\Users\ouyan\Documents\Obsidian Vault\Embedded_Learning\`

## 1. 名称与定位

`embedded-learning-mentor`（嵌入式工程学习导师）：用真实工程项目实践培养**独立的嵌入式能力**。成功标准是“用户下次遇到同类问题，能自己查手册、自己定位、自己验证”。

## 2. 核心能力

- 9 种模式：讲解、规划、实践、调试、审查、检索、档案、硬件、诊断。
- 知识等级 L0–L4（状态）+ 教学介入 T3–T0（本次给多少答案），两者解耦。
- 七条红线：官方文档为据、不伪造结果、标注不确定、先测水平、不越权代做、档案只写真事实、高风险先同意。
- 15 篇参考：教学法、诊断、规划、工程、编码、硬件、PCB、调试、资料、知识库、记忆、工具、协作、安全、领域。
- 三层记忆：个人档案 + 学习状态 + 项目经验；文件是事实源，Mnemon 只存摘要。
- Obsidian Vault 知识库 + `archive.py`（init/status/check/audit/new-log）。
- 11 个技术领域：51、STM32、C/C++、数模电路、PCB、通信、RTOS、Linux、机器人等。

## 3. 适用任务

- 学嵌入式、制定学习路线、评估当前水平。
- 嵌入式项目陪练、方案/选型、原理图/时序分析。
- 硬件调试（电源、GPIO、时钟、复位、接口、信号）。
- 代码审查（学习目的）、错误复盘、学习档案维护。
- 查芯片/协议/工具链/电气参数（官方源优先）。

## 4. 不适用任务

- 真实项目大规模改码/跑测试/交付 → `engineering-assistant`。
- 项目排期/里程碑/验收/复盘 → `project-orchestrator`。
- 开放式多源调研/选型报告 → `research-engine`。
- 正式讲义/教材成稿 → `knowledge-content-engine`。
- 交互式 HTML → `offline-learning-html`。
- 纯软件工程/非嵌入式项目 → EA。

## 5. 调用与触发

- **自动**：出现“学嵌入式/STM32/51/PCB/通信协议/硬件调试/学习路线/评估水平”等意图时可加载。
- **显式**：说“用 embedded-learning-mentor 带我学/帮我排查”。
- 本 Skill 不调用其他 Skill；跨 Skill 交接按 `guides/handoff-contract.md`。

## 6. 推荐的自然语言请求

- “我想 3 个月入门 STM32，先测一下我现在的水平，再给路线。”
- “I2C 收不到数据，现象是 …，帮我分层排查，先别改代码。”
- “审一下这段 GPIO 驱动，按学习目的讲，不要直接给完整答案。”
- “复盘这个项目，更新我的学习状态和错误台账。”

## 7. 所需输入

| 项 | 必填 | 说明 |
|---|---|---|
| 学习目标/任务 | 是 | 学会/做完/排查/评估 |
| 当前水平 | 否 | 没档案时做 ≤4 题诊断 |
| 芯片/项目 | 是 | 型号、开发板、工具链 |
| 现象与证据 | 调试必填 | 报错、波形、接线、已排除项 |
| 时间预算 | 规划必填 | 每周可投入 |
| 代码/原理图 | 审查必填 | 路径或片段；片段要说明上下文 |

## 8. 预期输出

- 讲解：结论 → 直觉模型 → 机制 → 手册依据 → 最小实验 → 常见坑。
- 规划：目标/约束 → 2–3 条路线 → 取舍/周期 → 阶段/里程碑 → 待确认。
- 评估：已评知识单元 → L 级 + 证据 → 缺口 → 下一步训练。
- 调试：现象 → 已排除 → 下一步实验 + 判据 → 需要你提供的信息。
- 审查：六要素 + 分级；工程任务：档位/步骤/验收/风险/证据等级。
- Vault 日志/状态/项目档案/错误台账。

## 9. 可复制提示词

```text
用 embedded-learning-mentor 带我学 <主题>。
我的水平：<已学/项目经验>；目标：<能做到什么>；时间：<每周几小时>；硬件：<芯片/板子>。
先做 ≤4 题诊断，再给 2–3 条路线；学习模式不要直接给完整代码，给判据和下一步。
```

## 10. 典型场景

- 零基础/转行嵌入式路线。
- STM32 外设/RTOS/通信协议学习。
- 硬件故障分层排查。
- 项目复盘与错误台账。
- 查数据手册/参考手册/勘误。

## 11. 与其他 Skill 协作

| 对象 | 交接 |
|---|---|
| `engineering-assistant` | ELM 教、EA 做；真实改码/测试交 EA，ELM 记录学习点 |
| `research-engine` | 多源选型/对比交 RE；单参数查手册 ELM 自己做 |
| `knowledge-content-engine` | 讲义/教材成稿交 KCE；ELM 提供学习目标/练习/学习者画像 |
| `offline-learning-html` | 交互页交 OFF；ELM 提供目标/练习，检查学习效果 |
| `project-orchestrator` | 多阶段项目交 PO；ELM 管学习计划，PO 管项目验收 |

## 12. 常见错误与排障

| 现象 | 处理 |
|---|---|
| 没有档案 | 做 ≤4 题诊断；记“待评估”，不假设 L0 |
| Memory Spaces 不可用 | 0 空间/Provider 未连接；档案落 Vault，不假装写入 |
| Documents 计数变化 | 以 `mnemon_status` 实测为准；摘要允许过期，回源文件核对 |
| 硬件未实测 | 标 BLOCKED/V5 只能由用户提供；不写“烧录成功/波形正常” |
| 51 无 SDCC/Keil | 只能讲解/审阅，不声称编译 |
| Git 不在 PATH | 用 `C:\Program Files\Git\cmd\git.exe` 绝对路径 |
| 用户要“直接给答案” | 压缩讲解但保留一句“为什么”和一个自检问题；交付场景可直接给 |

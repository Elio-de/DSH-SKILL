# 知识沉淀与研究更新（M13 K1–K4）

> 职责：K1–K4 目录语义、命名与编号、版本与变更、更新流程、索引、Documents 可选通道。
> 适用：S15–S16。不适用：报告骨架（`delivery.md`）、契约字段（`schemas/`）。

## 1. 研究根目录

`research/`（Q-01 已决策，2026-11-18）。单次研究：`research/<topic-slug>/`，`topic-slug` 为 kebab-case（英文小写、连字符、≤40 字符）。

> **与 `researchId` 的区别**：目录用 slug（人可读、可改）；`researchId`（`R-YYYYMMDD-NNN`）是契约字段（稳定、不可复用），两者在 `K4-index/index.md` 与 `research/_index.md` 中一一对应登记。

```text
research/
├── _index.md          # 全局索引：主题 → 目录 → 状态 → 版本 → 更新日期
├── _preferences.md    # 可选：用户长期偏好（不得含安全规则）
├── _test/             # 测试临时产物（不进正式研究目录）
└── <topic-slug>/
```

## 2. K1–K4 四层（FR-058）

| 层 | 内容 | 写权限 | 关键要求 |
|---|---|---|---|
| K1-sources/ | 原始资料快照 + 元数据卡（URL、抓取时间、快照路径） | 只新增，不覆盖 | 每条 `S-001.md` 可回指 URL |
| K2-reports/ | 历史版本报告副本 | 只新增 | 每次交付归档一份 |
| K3-knowledge/ | 经整理与验证的结论、技术知识、方案、经验 | 可追加 | 每条可回指 K1/K2 |
| K4-index/ | 主题索引、关联资料、文件路径、版本与更新记录 | 可追加 | 新会话先读它定位 |

**验收口径**：T02 类研究 K1–K4 均非空；K3 每条可回指；索引能定位到文件。

## 3. 命名与编号（稳定、不复用）

| 对象 | 规则 | 示例 |
|---|---|---|
| 研究目录 | `topic-slug` | `stm32h743-vs-f407-motor` |
| 笔记 | `NN-<slug>.md` | `01-performance.md` |
| 来源 | `S-###` 三位递增 | `S-007` |
| 证据 | `E-###` | `E-042` |
| 结论 | `C-##` | `C-03` |
| 冲突 | `X-##` | `X-01` |
| 假设 | `A-##` | `A-02` |
| 反方 | `CR-##` | `CR-01` |
| 局限 | `L-##` | `L-01` |
| 后续 | `N-##` | `N-01` |
| 研究 ID | `R-YYYYMMDD-NNN` | `R-20261118-001` |
| 数据版本 | `MAJOR.MINOR.PATCH` | `1.0.0` 首次；`1.1.0` 新增证据；`2.0.0` 结论改判 |

**编号稳定性**：只增不改；删除内容保留编号并标 `invalidated`，禁止回收。

## 4. 覆盖与冲突策略

| 场景 | 策略 |
|---|---|
| 目录已存在 | 自动加 `-v2` 后缀并提示，不覆盖原目录 |
| 报告更新 | 不覆盖 `report.md`，生成 `report.v2.md`，确认后由用户/S16 流程替换 |
| 证据/来源清单 | 只追加；修改通过 CHANGELOG 记录 |
| 结论状态 | `superseded` + `supersededBy`，正文保留 |
| 日志 | 只追加 |
| K1 快照 | 只新增 |
| 下游派生 | 只能写 `derived/` |

**默认拒绝覆盖**（SEC-004）：目标已存在 → 先检查内容与版本 → "新增版本"或"报告冲突"。

## 5. 更新流程（S16，FR-061/FR-062）

```text
触发：用户说"更新这个研究" / 新资料出现 / 外部调度（S01 自身不定时运行）
① 读 K4 索引与既有 research_result
② 重检关键来源：URL 可达性、published/updated、版本、维护状态
③ 对比新旧证据；识别受影响结论
④ 生成 update-report.md（新增/变更/失效/影响/建议）
⑤ 旧结论标 superseded；追加 CHANGELOG；更新 K4 索引
⑥ 通知用户变更摘要（不自动替换现行版本）
```

**边界**：S01 不自行定时运行（LIM-006）；"定期复查"由用户或 `schedule` 触发。

## 6. 跨会话访问（FR-059）

| 通道 | 用法 |
|---|---|
| 工作区文件 | **主通道**：新会话 `read`/`glob`/`grep` 直接读 |
| K4 索引 | 新会话先读 `research/_index.md` 定位 |
| Mnemon Documents | 补充通道（可选，Q-05 未决不默认写） |
| Runtime memory | 不作为研究事实源 |
| 其他会话聊天记录 | 不可检索，禁止设计"翻上一个会话" |

**验证方法**：新会话仅凭 `report.md` + `research_result.json` + K4 索引，能复述结论与证据链。

## 7. Documents 可选写入（FR-060，P2）

- 仅当 `mnemon_document_create` 可用时执行；写入摘要 + K4 索引回填 `documentId`。
- 失败不阻断：记 `documentsUnavailable`，继续交付。
- **不得**作为唯一存储；关闭后研究仍完整。
- Q-05 未决 → **不默认写入**；用户显式要求时才写。

## 8. 反例

- 直接覆盖 `report.md` 导致历史丢失 → 违规。
- K3 条目无法回指 K1/K2 → 索引失败。
- 把结论只留在对话里 → FR-059 违规。
- 承诺"每天自动监控更新" → LIM-006 违规。

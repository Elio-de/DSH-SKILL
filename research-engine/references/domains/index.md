# 领域策略索引（M08）

> 职责：九类领域到策略文件的路由、组合规则、缺失降级。
> 适用：S2 判定领域后。不适用：具体必查维度（在各领域文件内）。

## 1. 路由表（FR-037 / FR-038）

| 领域 | 文件 | 何时命中 |
|---|---|---|
| 技术研究（通用） | 无文件 → 用 §5 通用策略 | 未细分到具体领域的技术问题（如"HTTPS 为何安全"） |

## 2. 组合规则

- 一个任务可命中**多个**领域：按 `primaryDomains` 加载 **1–2 个**领域文件（最多 2 个）。
- 组合顺序：先 `primaryDomains[0]`，再补第二个的**额外必查项**；冲突时以"更严格"的时效与来源要求为准。
- 全部写入 `meta.strategiesApplied[]`（路径形式，如 `references/domains/embedded.md`）。

## 3. 常见组合

| 任务 | 组合 |
|---|---|
| 芯片选型 | embedded + programming（生态/工具链） |
| GitHub 项目生产可用性 | programming + industry（供应链/法律另见 github.md） |
| 技术标准版本变化 | legal-policy + embedded |
| AI 技术综述 | academic + ai-cs |
| 行业薪资调研 | career + industry |

## 4. 缺失与降级

- 领域文件缺失 → 用通用策略（本索引 §5）+ 在 `limitations[]` 记录"领域策略缺失，按通用策略执行"。
- 领域判定不确定 → 取最接近的一个 + 通用策略，并在 `modeBasis`/`rigorBasis` 说明。
- **不得**因为缺文件而跳过该领域的"必查维度意识"——至少按通用维度检查版本、口径、时效。

## 5. 通用策略（fallback）

1. 明确对象与版本/时间范围。
2. 优先第一层来源（官方/标准/原文）。
3. 关键结论 ≥2 独立来源（L2+）。
4. 检查时效与适用范围。
5. 检查冲突并归因。
6. 说明局限与不确定性。
7. 数据类结论标 `dataKind` 与口径。

## 6. 扩展方式

新增领域：新建 `references/domains/<name>.md`（含检索偏好、≥5 必查维、陷阱、验收、时效）→ 在本表加一行 → 主 `SKILL.md` **无需改动**（NFR-007 / FR-039）。

# 受理与澄清（brief、来源政策、缺口、输入格式、配置）

> 职责：把用户请求规范化为 `brief`；确定来源政策；决定提问或假设；登记缺口；识别输入格式与转换意向；处理三级配置。
> 读取时机：S1；用户补充素材或修改目标时；配置冲突时。
> 不重复：模式判定见 `mode-selection.md`；来源评级见 `evidence.md`。

## 1 brief 九字段

| 字段 | 含义 | 缺失处理 |
|---|---|---|
| `title` | 文档标题 | 可由主题推导 |
| `purpose` | 「读者读完能（动词）（对象）」 | **不得为 unknown**：缺失时按主题写可判定假设并登记，或直接降完成度 |
| `audience` | 角色/前置/场景/语言水平 | 可假设并写入 assumptions；若受众会改变内容方向且为 C2/C3 → 提问（见 §4） |
| `scope.inScope[]` | 覆盖范围 | 可推导 |
| `scope.outOfScope[]` | 明确排除 | 可推导 |
| `deliverableFormat` | Markdown / 转换形态（仅显式） | 默认 Markdown |
| `detailLevel` | C1/C2/C3 | 默认 C2 |
| `language` | 输出语言 | 默认 zh-CN |
| `constraints` | 篇幅/时间/版本/合规/练习要求 | 可假设 |

**验收**：九字段均存在（`purpose` 不得 unknown，其余可为 unknown）；`purpose` 用统一句式；缺失字段若被假设，必须同时出现在 `assumptions[]`。

## 2 来源政策（三态）

| 政策 | 含义 | 允许动作 | 缺口处理 |
|---|---|---|---|
| `provided-only` | 只用用户提供资料 | 不联网 | 标 `unverified` 或请求补充 |
| `provided+verify`（默认） | 提供资料 + 定向核验 | 为具体断言做有限读取（≤预算） | 核验失败标 `unverified` |
| `research-request` | 需要补充研究 | 生成 `research-request.md`，不自行做开放式调研 | 交用户发起 S01 |

## 3 参与分级

| 档位/场景 | 是否提问 | 行为 |
|---|---|---|
| C1 简单任务（单文件、素材充分） | 不提问 | 直接执行；假设写入 assumptions |
| C2 一般任务 | 仅关键信息缺失时 | 说明合理假设后执行；≤3 问合并 |
| C3 复杂/重大内容 | 关键缺口 ≤3 问 + 计划确认 | 计划确认不算澄清；可跳过但记录 |
| 简单级但模式歧义 | 最多 1 问 | 不答则按动词默认，不再追问 |

**禁止**：用提问代替可检索/可推断的信息；同一问题重复问；把计划确认伪装成澄清。

## 4 澄清判定树

```text
缺失信息是否改变内容方向？
 ├─ 是 → 能否通过资料/推断解决？
 │        ├─ 是 → 假设并记录
 │        └─ 否 → 提问（合并 ≤3）
 └─ 否 → 是否影响安全提示/不可逆操作授权？
          ├─ 是 → 提问
          └─ 否 → 假设并记录
```

**必问场景**：目标读者会改变内容方向（C2/C3）；交付形态涉及不可逆转换授权；安全/合规边界不清。
**不必问**：C1 任务；用户显式要求"别问"；版本号、API 名称、默认参数（可查资料）；用户已在上文说明的信息。

**优先级**：用户显式"免问" > C1 不提问 > 受众影响方向时提问；任何跳过都要写 `assumptions[]` 与理由。**无交互通道**（批处理/子代理/无人应答）时一律按假设继续，`openQuestions` 标 `closed:no-channel`。

## 5 提问模板（合并为 ≤3）

- 模式歧义："要能照着执行的文档，还是帮助读者学会的教材？"
- 受众缺失："读者是工程师/操作员，还是零基础学习者？"
- 范围缺失："覆盖哪些版本/章节？不覆盖什么？"
- 转换确认：仅当用户已说"转成 X"时，确认执行方式与授权；不主动询问。

## 6 假设与缺口

`assumptions[]`：

```json
{ "id": "AS-01", "statement": "假设读者具备 C 语言基础", "impact": "ch02 不解释指针语法" }
```

`gaps[]`：

```json
{ "what": "缺少 v2.3 官方参数表", "why": "CH-03 参数结论无法核实", "options": ["用户补充", "research-request", "定向核验", "标 unverified"], "disposition": "定向核验" }
```

- critical 缺口必须处置（补资料/降级/标未验证），不得静默忽略。
- `research-request.md`：缺口清单 + 所需证据类型 + 优先级 + 期望时限；交用户发起 S01，**不运行时调用**。
- **练习豁免**：仅当用户明确说"不要练习/只要自测/精简版"时，在 `brief.constraints` 写 `exerciseExempt: true` 并记录用户原话；否则一律按 `learning.md §7` 默认完整练习，不得自行豁免。

## 7 输入格式与可读性

| 格式 | 检查 | 降级 |
|---|---|---|
| Markdown/TXT | UTF-8、非空、结构可识别 | 转码/报错 |
| 代码/CSV/JSON | 可解析、有表头/字段 | 说明格式问题 |
| DOCX/PPTX/XLSX/PDF | office 读取能力探测（`office_status`） | 不可用 → 请用户导出 Markdown/PDF |
| 图片 | `read_image` 可读；无 OCR | 只引用可读信息；扫描件请提供文本 |
| URL | 可访问；记录抓取时间 | 不可达 → 记录并标 `unreachable` |

**禁止**：把空内容当"来源不存在"；把壳页/登录墙当正文。

## 8 转换意向（仅显式）

- 触发（**按意图判定**，不要求字面词）：用户要求产出或交付其他格式，如"转成/导出为 Word/DOCX/PPT/PDF/思维导图"、"直接给我 PDF 文件"、"要个 Word 版"、"做成 PPT"。
- 默认：**不询问、不生成转换请求**。
- 识别后：记录 `conversionIntent{target, explicit: true, sourceQuote}`，S11 进入 G6 分支。
- 禁止：把"以后可能要 Word 版"当成明确请求；把"Markdown 就行"当成转换请求。

## 9 三级配置

| 层级 | 载体 | 可覆盖 | 不可覆盖 |
|---|---|---|---|
| 全局默认 | `SKILL.md` + `workflow.md` | 流程、预算默认、门禁 | SEC 安全底线、不编造规则 |
| 类型配置 | `profiles/<type>.md` 的"默认参数"节 | 档位默认、预算档、练习策略、章节骨架 | 同上 |
| 单次任务 | 用户指令 / brief | 模式、档位、语言、目录、预算、是否转换 | 同上 |

- 优先级：任务 > 类型 > 全局。
- 记录 `configSources[]`：`{key, value, source ∈ global|profile|task}`。
- 可审计：`review.md` 记录六项参数（模式/档位/语言/目录/预算/练习策略）及来源。

## 10 输出

- `brief` 写入 manifest 草稿与 `outline.md` 头部。
- `sourcePolicy`、`gaps[]`、`assumptions[]`、`openQuestions[]` 写盘。
- 转换意向只写记录，不生成请求。

## 11 压缩与提档（用户中途改口径）

| 请求 | 处理 |
|---|---|
| 压缩/精简（"压成 1 页""只要摘要"） | 默认生成派生件 `derived/summary.md`（另交一份短文档）；若用户明确说"这份讲义不要练习/精简本讲义"，则视为**配置变更**：改主件并记录 `exerciseExempt`/范围变化，不生成派生件。两者同命中时先问一句"另交一份，还是改这份？"；无通道则默认派生件。 |
| 提高专业深度（"更专业""专家级"） | 提档需说明影响（章节/预算/证据量）；C2→C3 建议确认，无通道则记录假设；通过增加证据、边界、版本差异、失败模式实现，**不得只换形容词**；重跑 G3/G5 |
| 降低难度/面向新手 | 增加前置解释与例子，标 `[简化]`；事实与参数不得降级 |
| 缩短篇幅但保留完整性 | 优先删重复与过渡，不删断言依据、验证状态、风险 |

**禁止**：用"更专业/更通俗"的空话替代实际内容变化；压缩时悄悄降低验证等级。

## 2 目标与范围

- **目标（可衡量）**：8 篇源文档全部登记且路径唯一；5 个元数据字段完整率 100%；索引页离线双击打开、无外部资源、控制台报错 0；主题筛选与关键字过滤结果与清单一致；断链与失效锚点 0；非项目成员按交付说明 5 分钟内定位任意 1 篇。
- **范围内（in）**：① 文档清点与清单；② 元数据抽取与统一；③ 主题归类（6 主题、一篇一主主题）；④ 单文件静态索引页；⑤ Markdown 镜像索引；⑥ 断链与锚点自检；⑦ 用户抽样验收与 1 轮修订。
- **范围外（out）**：① 不重写或翻译文档正文；② 不迁移、删除、改名源文档；③ 不接后端服务、不做全文检索引擎；④ 不上传或发布到任何平台；⑤ 不做权限与账号管理；⑥ 不逐字抽取 PDF 正文。
- **不做什么的判定**：凡需要联网抓取、外部服务、改写源文档或对外发布的需求，一律判为越界；越界需求必须先写入 `变更记录（CHANGELOG）.md` 并由用户确认后才可评估。
- **成功标准与验收口径的对应**：离线无依赖 ↔ `AC-004`；打开无报错 ↔ `AC-005`；条目与筛选一致 ↔ `AC-006`、`AC-007`；断链 0 ↔ `AC-009`；5 分钟定位 ↔ `AC-010`。

## 6 流程与中断说明

**主流程**：S0 能力探测 → S1 立项（G0）→ S2 需求基线（G1）→ S3 规划与拆解 → S4 规划质量自检（G2）→ S5 派发 → S6 执行（每里程碑 G3）→ S7 验收（G4）→ S8 归档与复盘（G5）→ CLOSED。

**文件即状态**：任务完成、问题发生、决策做出、计划变更、风险变化、阶段结束、交付物产生，任一事件都在 `项目进度（PROGRESS）.md` 追加一行，并同步对应档案；对话记忆不作为事实源，冲突时以档案为准。

**中断与恢复**：① 恢复顺序 = 本 README → `PROGRESS` 末 3 行 → `TASKS` 中状态非 Done 的任务 → `RISKS` 状态为开放/已发生的条目；② 中断超过 1 天、或需求/技术路线/资源发生重大变化，按 `规划质量报告（PLAN_QUALITY）.md` 的 Q1–Q8 触发重检；③ 已 Done 任务返工必须先建 `CHANGELOG` 条目并升版本；④ 不可逆操作（覆盖、删除、外发、发布）必须获得用户明确授权并先备份，未获授权时暂停该项并给出替代方案。

**变更路径**：提出申请 → 影响分析（RQ/AC/TK/MS/DL 全链）→ 判定权限（目标/需求/验收标准必须用户确认）→ 建 CH 条目 → 更新受影响档案 → 重检 → 追加 PROGRESS 记录。

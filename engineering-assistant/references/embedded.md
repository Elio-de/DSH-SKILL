# 嵌入式专项（embedded）

> 本文件是 `coding` / `review` / `testing` 的**增强检查表**，不是独立流程。
> 适用：51、STM32、其它 MCU 的 C/C++ 固件。
> **最高原则：涉及具体芯片时，一切寄存器与外设行为必须以该芯片型号对应的数据手册/参考手册为准，不得凭经验臆测地址或位定义。**

---

## 1 数据类型与整数溢出

| 检查点 | 常见错误 | 怎么查 |
|---|---|---|
| 用 `int` 表示硬件宽度 | 8 位机 `int` 是 16 位，32 位机是 32 位 | 一律用 `stdint.h`：`uint8_t/uint16_t/uint32_t` |
| 隐式提升 | `uint8_t a=200, b=100; a+b` 在 int 里算，再截断回 8 位 | 用 `-Wconversion`；显式强转并注释 |
| 有符号/无符号比较 | `int i` 与 `sizeof()` 比较恒真/恒假 | 统一 `size_t`，或显式转换 |
| 计数器回绕 | `tick++` 溢出后判断 `>` 出错 | 用无符号差值：`(uint32_t)(now - last) > timeout` |
| 移位 | `1 << 31`（有符号溢出）、`1 << 32`（UB） | 用 `1u << n`，`n < 位宽` |
| 除法/浮点 | 无 FPU 的 MCU 上用 `float` 除法 | 定点运算或 `-mfpu` 明确配置 |
| 类型宽度假设 | 假设 `long` 是 4 字节 | 用 `int32_t` |

**验证**：`arm-none-eabi-gcc -Wall -Wextra -Wconversion -Wsign-compare`，逐条看告警。

## 2 指针与数组边界

- 数组长度用 `sizeof(arr)/sizeof(arr[0])`，**不要**在函数参数里这么算（退化为指针）；
- 传缓冲区必须**同时传长度**；
- `memcpy/memset/strcpy` 的长度来源必须校验；
- 栈上大数组 → 栈溢出（见 §5）；
- 指针算术越界是 UB，编译器不保证报错；
- 函数指针未判空就调用（回调注册可失败）。

```c
/* 反例：buf 长度未知 */
void fill(uint8_t *buf) { for (int i = 0; i < 16; i++) buf[i] = 0; }
/* 正例 */
void fill(uint8_t *buf, size_t cap) { for (size_t i = 0; i < cap; i++) buf[i] = 0; }
```

## 3 内存使用

```powershell
arm-none-eabi-size build\firmware.elf
arm-none-eabi-nm --size-sort -S build\firmware.elf | Select-Object -Last 20
```

| 段 | 含义 | 关注点 |
|---|---|---|
| `.text` | 代码 + 常量 | Flash 占用；字符串常量也在这里 |
| `.data` | 已初始化全局/静态变量 | 占 Flash（初值）+ RAM（运行时） |
| `.bss` | 未初始化全局/静态变量 | 只占 RAM |
| heap / stack | 运行时 | 见 §5 |

**常见问题**：
- 大数组没加 `const` → 白占 RAM；
- 大 `const` 表放在 `.data` 因为没加 `const`；
- 动态内存（`malloc`）在长期运行的固件里导致碎片 → **优先静态池**；
- 对齐：DMA 缓冲区、位域访问、结构体打包（`__attribute__((packed))` 有性能与对齐代价）。

## 4 中断与共享变量

### 4.1 `volatile` 判定表（最常被误用）

| 场景 | 需要 `volatile`？ | 说明 |
|---|---|---|
| ISR 写、主循环读的标志 | **是** | 否则编译器可能优化成只读一次 |
| 主循环写、ISR 读（8/16/32 位对齐单次访问） | **是** | 保证每次都从内存取 |
| 纯局部变量 | 否 | 无共享 |
| 函数参数 | 否（除非指向共享内存） | — |
| 外设寄存器 | 通常由厂商头文件处理 | 用 `HAL_`/CMSIS 定义，不要自己乱加 |
| DMA 缓冲区 | **是** + 考虑缓存/屏障 | 若开了 D-Cache，还需 clean/invalidate |
| 多字节共享结构 | `volatile` **不够** | 需要临界区/关中断保护 |

**关键认知**：`volatile` 解决"编译器优化"，**不解决**原子性与竞态。

### 4.2 临界区

```c
uint32_t primask = __get_PRIMASK();
__disable_irq();
/* 读-改-写共享数据 */
__set_PRIMASK(primask);   /* 恢复而不是无条件开中断 */
```

要检查的：
- 是否恢复原状态（不是无脑 `__enable_irq()`）；
- 临界区是否过长（影响实时性）；
- 是否在中断里又开了中断（嵌套风险）。

### 4.3 ISR 纪律

| 禁止 | 原因 |
|---|---|
| 在 ISR 里 `printf`/阻塞发送 | 耗时、可能重入死锁 |
| 在 ISR 里 `malloc/free` | 非可重入 |
| 在 ISR 里做长循环/延时 | 拉高最坏中断延迟 |
| 在 ISR 里调用非可重入函数 | 竞态 |
| 忘记清中断标志 | 反复进中断 / 卡死 |

**正确模式**：ISR 只做"取数据 + 置标志 + 唤醒处理"，重活放主循环。

## 5 栈空间（最容易静默崩溃的地方）

```powershell
arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb -fstack-usage -c src\x.c -o build\x.o
```

生成 `x.su`，每行给出函数的栈帧字节数。手工累加调用链最深处 = 最坏栈用量。

检查点：
- 启动文件/链接脚本里的栈大小（`_Min_Stack_Size`）是否留够余量（建议 ≥ 最坏值 × 1.5）；
- 是否有递归（嵌入式里几乎都应避免）；
- 大局部数组（如 `uint8_t buf[1024]`）是否该改静态；
- 中断嵌套会增加栈用量（每个嵌套一层）。

51 特别说明：51 的栈在内部 RAM，深度受 `idata` 大小限制，且**没有可靠的栈溢出检测**；递归与深层调用必须避免。

## 6 定时器与时钟配置

必须核对的三级：**时钟源 → 分频 → 计数/重载**。

```
定时时间 = (PSC + 1) × (ARR + 1) / TIM_CLK
```

检查清单：
- 定时器挂在哪条总线（APB1/APB2），实际频率是多少（分频器可能×2）；
- `PSC`/`ARR` 是否在 16/32 位范围内；
- 是否需要更新中断（`DIER.UIE`），中断里是否清标志（`SR.UIF`）；
- 有没有考虑溢出回绕；
- 用 SysTick 还是 TIM 做时基，是否与 RTOS 冲突；
- 低功耗模式下时钟是否被关掉。

**常见 bug**：算出的定时时间与实测差 2 倍/8 倍 → 十有八九是时钟树理解错（把 APB 分频后的频率当成了定时器时钟）。

## 7 外设初始化顺序

标准顺序（顺序错会静默失败）：

```
1. 使能外设时钟（__HAL_RCC_xxx_CLK_ENABLE）   ← 最常忘
2. 配置 GPIO（模式/复用/上下拉/速度）
3. 配置外设本体（参数结构体 + Init）
4. 配置 NVIC（优先级、使能）
5. 使能外设
6. （DMA 场景）配置 DMA 通道并关联
```

检查点：
- GPIO 复用功能编号是否与外设匹配（同一引脚可能对应多个 AF）；
- 中断优先级分组（`NVIC_SetPriorityGrouping`）是否与全系统一致；
- 外设复位（`__HAL_RCC_xxx_FORCE_RESET/RELEASE_RESET`）是否需要；
- 初始化顺序是否受 `MX_*_Init()` 调用顺序影响（如先 UART 后时钟配置）。

## 8 GPIO 配置

| 项 | 要确认 |
|---|---|
| 方向 | 输入/输出/复用/模拟（模拟用于 ADC） |
| 输出类型 | 推挽（默认）/ 开漏（I²C、电平转换、线与） |
| 上下拉 | 浮空输入必须外部有确定电平，否则加内部上下拉 |
| 速度 | 高速信号用 High，低速用 Low 降低 EMI |
| 复用编号 | 查数据手册 AF 表，**不同封装可能不同** |
| 初始电平 | 输出前先设 ODR，避免上电毛刺 |
| 未使用引脚 | 建议配置为模拟或明确电平，降低功耗 |

**硬件匹配检查**（与原理图/引脚表对照）：
- 固件里 `LED_PIN`/`UART_TX_PIN` 的端口与引脚号是否与原理图一致；
- 复用功能是否与外部器件要求一致（如 USART2 的 TX 在某封装上是 PA2 还是 PD5）；
- 上下拉是否与外部电路冲突（外部已有上拉还开内部上拉 → 阻值变化）；
- 5V 器件直连 3.3V MCU 引脚 → 电平不匹配（需电平转换）。

需要用户提供：原理图引脚表、`.ioc` 文件、或网表导出。**没有依据时明确说"无法核对，需要你提供引脚表"**。

## 9 寄存器操作

**规则**：
1. 地址与位定义**必须**来自该型号的参考手册（RM）或 CMSIS 头文件；
2. 不凭记忆写 `0x4001 1000` 之类的地址；
3. 位操作优先用 `|=` / `&= ~`，避免影响同寄存器其它位；
4. 读-改-写序列在中断可能打断时要保护；
5. 有些寄存器"写 1 清零"、有些"读后清零"——必须查手册。

```c
/* 可接受：用厂商定义 */
GPIOA->ODR |= (1u << 5);
/* 不可接受：硬编码地址/魔数位 */
*(volatile uint32_t *)0x40020014 |= 0x20;
```

若用户给的芯片型号不明确 → **先问型号**，不要猜。

## 10 实时性

| 检查 | 说明 |
|---|---|
| 最坏中断延迟 | ISR 是否过长；是否有高优先级长时间关中断 |
| 主循环周期 | 最长路径耗时是否满足采样/通信周期 |
| 阻塞调用 | `HAL_Delay`、忙等 `while(!flag)` 是否出现在关键路径 |
| 优先级反转 | 低优先级持锁、高优先级等待 |
| 看门狗 | 喂狗位置是否在主循环（若在某任务里，该任务卡住会喂不到） |
| 抖动 | 是否有不定长操作（如 `printf` 格式化） |

**注意**：实时性结论没有测量就是推断（V1/V2）。要证据 → 需要 GPIO 翻转 + 示波器/逻辑分析仪，由用户执行。

## 11 芯片手册使用纪律

| 需要的信息 | 查哪里 |
|---|---|
| 引脚复用、封装引脚号 | 数据手册（Datasheet）引脚定义表 |
| 寄存器地址/位域/时序 | 参考手册（Reference Manual） |
| 电气特性、电压、电流 | 数据手册 Electrical Characteristics |
| 勘误（Errata） | 芯片 Errata Sheet（**必须查**，很多坑在这） |
| Flash/RAM 大小、启动地址 | 数据手册 + 链接脚本 |

**禁止**：把别的型号（如 F103 的寄存器）套用到 F4/H7；不同系列外设差异很大。

需要联网查手册时：说明查什么型号的哪一章节，取回后引用章节号，不整段抄。

## 12 常见陷阱速查

| 现象 | 高概率原因 |
|---|---|
| 上电就跑飞 / HardFault | 栈溢出、向量表地址错、时钟没配就访问外设 |
| 随机死机，复位后正常 | 栈溢出、野指针、未初始化指针、看门狗 |
| 串口乱码 | 波特率时钟源算错、GPIO 复用错、电平不匹配 |
| 中断只进一次 | 没清中断标志 |
| 中断进不去 | NVIC 未使能、优先级分组错、外设中断未开 |
| ADC 读数漂移 | 参考电压不稳、采样时间不足、引脚配置成数字 |
| I²C 卡死在忙等 | 从设备无应答、缺上拉、时序过快 |
| PWM 无输出 | 定时器通道未使能、复用未配、比较值超 ARR |
| 低功耗电流下不去 | 未用引脚悬空、外设时钟未关、调试器未断开 |
| 程序大小突然暴涨 | 引入了浮点格式化/大常量表/调试字符串 |

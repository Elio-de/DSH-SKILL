# 改前自检（pre-change）

> 任何修改源文件之前，逐条打勾。任一条答不上来 → 先补，不要动手。

## 一、理解

- [ ] 我**读过**要改的文件，能说清它现在在做什么
- [ ] 我知道这段代码的**调用者**（`grep` 过关键函数）
- [ ] 我知道**输入从哪来、输出到哪去**
- [ ] 我确认了这是**当前生效的代码**（不是死代码/未参与构建的旧文件）

## 二、范围与影响

- [ ] 我列出了**要改的文件清单**
- [ ] 我列出了**不改的部分**（防止范围蔓延）
- [ ] 我判断了是否触及**公开接口 / 数据结构 / 构建配置**
- [ ] 如果触及，我说明了兼容性影响

## 三、安全

- [ ] 这次改动**不覆盖**用户未提交的其它修改
- [ ] 大改前已备份到 `.ea/backup/<时间戳>/`，并写了 `NOTE.md`
- [ ] 我**没有**计划删除任何文件（若需要 → 先请求授权）
- [ ] 我**没有**计划运行来源不明的脚本

## 四、验证方案

- [ ] 我知道改完**怎么编译**（具体命令）
- [ ] 我知道改完**怎么测**（具体用例或命令）
- [ ] 如果是嵌入式硬件相关，我知道**哪些只能由用户验证**
- [ ] 我记录了改动前的基线（编译状态 / 测试通过数）

## 五、回退

- [ ] 如果改错了，我能**退回去**（备份/逆向 edit/明确步骤）
- [ ] 回退步骤我能写出来（写不出 = 不能开始）

---

**通过标准**：以上全部打勾。否则先补齐信息，或把任务降级为"只分析、不改动"。
